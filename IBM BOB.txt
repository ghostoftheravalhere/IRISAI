Submission for IBM SkillsBuild Hackathon

2. ROLE OF IBM BOB
IBM Bob was utilized as an AI-assisted development and engineering companion throughout the lifecycle of the IRIS AI project. IBM Bob served as an intelligent assistant to accelerate research, architecture reasoning, code analysis, debugging, and technical documentation.

All final architectural choices, design decisions, implementation details, runtime testing, and overall project directions were strictly evaluated, reviewed, executed, and maintained under the human oversight and control of the student development team.

IBM Bob was used during early design phases and technical planning to:
- Discuss and refine the end-to-end IRIS AI system architecture.
- Deconstruct the multi-modal system into clear, modular components:
  * User Input (Voice Capture, Gaze Tracking, Blink Gestures)
  * Perception (Faster-Whisper STT, MediaPipe Landmark Extraction)
  * Interpretation (Intent Parser, Entity Extractor, Context Fuser)
  * Action & Automation (ActionEngine, Centralized AppResolver, PyAutoGUI, Windows OS API)
  * Verification & Result (Telemetry EventBus, Assistant Response Generator, Dashboard UI)
- Reason about real-time interactions and data flow between voice recognition, gaze coordinate smoothing, intent classification, desktop controller, and the Electron/React interface.
- Help translate high-level accessibility goals into concrete technical specifications.
- Review candidate architectural decisions to spot potential bottlenecks, latency issues, and race conditions.
- Assist in mapping out the lifecycle of commands from speech recognition to desktop execution and visual response delivery.

6. DEBUGGING & TROUBLESHOOTING
IBM Bob assisted the student team in investigating and resolving critical real-world runtime bugs during IRIS AI development, including:

A. Voice Recognition & Conversational Flow:
   - Investigating speech recognition behavior and transcript normalization.
   - Debugging repeated/incorrect command classifications and false intent triggers.
   - Investigating edge cases where IRIS responses interfered with active listening.
   - Analyzing real-time microphone stream buffering and Voice Activity Detection (VAD) timing.

B. Audio Feedback & Self-Hearing Suppression:
   - Investigating why IRIS TTS audio output could accidentally re-enter the Whisper microphone input pipeline.
   - Analyzing microphone stream suppression techniques and half-duplex voice lifecycle states.
   - Investigating background speech worker threads and audio device lifecycle handling.
   - Establishing the V2.4 Submission Stability Mode configuration (`VOICE_OUTPUT_ENABLED = False`) with visual feedback to guarantee zero audio feedback during hackathon demonstration.

C. Application Lifecycle & Process Cleanliness:
   - Debugging backend process termination behavior during Electron app exit.
   - Investigating orphaned Python subprocesses surviving parent application exit on Windows.
   - Refining graceful SIGINT/SIGTERM process teardown with `taskkill /F` fallback in Electron `backendManager.js`.
   - Verifying that all background threads, microphone streams, camera loops, and FastAPI socket ports exit cleanly without memory leaks.

D. Desktop Automation & Application Resolution:
   - Debugging Windows application launch failures (e.g., why raw `start calculator` string execution failed in Windows shell).
   - Investigating critical intent resolution bugs where commands like "Open Microsoft Word" incorrectly fuzzy-matched to Microsoft Edge due to vendor name collisions.
   - Designing the `DesktopAppResolver` to resolve natural language app names dynamically via Start Menu `.lnk` shortcuts, Windows System executables (`calc.exe`, `notepad.exe`), and URI protocols (`ms-settings:`).
